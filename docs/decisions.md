# Ключевые архитектурные решения (ADR)

## 1. Почему LangGraph, а не CrewAI / AutoGen
Нужен явный контроль: условные рёбра, циклы с лимитом (Reviewer ≤ 2),
нативный interrupt/resume для human-in-the-loop, checkpointer для персистентности.
CrewAI/AutoGen — «разговоры агентов», где детерминизм и остановки контролировать тяжело.
Урок: enterprise требует предсказуемости, а не театра агентов.

## 2. Config-driven: бизнес в YAML, не в коде
Сигналы, скоринг, human_review, лимиты стоимости — в конфиге.
Доказано: 4 домена (realestate/law/logistics/medicine) без строчки кода.
Новый домен — 1 день.

## 3. Groq + fallback-список моделей
Скорость ~500 t/s, бесплатный tier.
УРОК (19.08.2026): llama-3.1-8b-instant и llama-3.3-70b-versatile сняты 16.08.2026 → 403 Forbidden.
Вывод: никогда не хардкодить одну модель; fallback-список + периодическая проверка /openai/v1/models.

## 4. DLP-Guard до LLM + урок false positive
PII не должен уходить за периметр — проверка ДО любого внешнего вызова.
УРОК: паттерн «цифра + 10-15 цифр» триггерился на размерах с чертежей (1530 3020 2570).
Вывод: телефон — только с явным префиксом +7/8(; DLP требует тюнинга и тестов (precision vs recall).

## 5. SqliteSaver + per-session thread_id
УРОК: SqliteSaver помнит состояние, а ChromaDB эфемерна → повторный запуск с тем же
thread_id давал пустой retrieved. Вывод: новый thread_id на сессию; в проде — персистентная векторная БД.

## 6. Гибрид: LLM + детерминированный скоринг
Скоринг — правила из конфига (как в n8n): предсказуемо и бесплатно.
LLM — только текст ответа. Надёжность + контроль стоимости.

## 7. FastAPI и Streamlit раздельно
API = контракт для краёв (n8n, интеграции). Витрина ходит в API по HTTP,
не трогая граф напрямую. Человеческое подтверждение — через /resume (Command resume).

## Growth points (следующая итерация)
Персистентная векторная БД, Langfuse, docker/k8s, внешние инструменты агентов
(web search/API), OCR-пайплайн для сканов (tesseract уже подключён).
